Для определения списка авторизованных операций (полномочий), который может производить в Системе зарегистрированный пользователь с определенной ролью (ролями), используются общие правила информационной безопасности, приведенные выше, и, дополнительно, следующие общие и дополнительные принципы.

Принцип экономичности реализации – правила разграничения доступа должны быть просты и понятны для персонала различной степени подготовленности и квалификации в области ИБ. Также простота реализации позволяет оптимально проводить аудит правильности назначения полномочий пользователя в Системе.

Принцип «наименьших полномочий» – каждому пользователю Системы должны быть предоставлены только те полномочия (и только на необходимое время), которые необходимы для выполнения им своих должностных обязанностей и функций. Исключением может быть временное повышение полномочий, которое должно проходить в исключительных случаях и непродолжительное время.

Принцип наиболее безопасных настроек по умолчанию – права доступа должны предоставляться пользователю по принципу «по умолчанию запрещено», а не «по умолчанию разрешено». В случае если происходит сбой Системы или контроля доступа, с точки зрения конфиденциальности и целостности правильнее блокировать полномочия уполномоченного пользователя по умолчанию. Однако для обеспечения доступности сервисов Системы в исключительных случаях для некоторых категорий пользователей необходимо предусмотреть набор высоких полномочий по умолчанию. 

Любые действия в Системе пользователя должны проводиться с использованием механизмов контроля доступа. Отключение механизма контроля доступа не допускается.

Полномочия любого пользователя должны периодически подвергаться плановому или выборочному аудиту.

Принцип «один пользователь один человек» – для выполнения большинства правил разграничения доступа необходимо, чтобы пользователь был однозначно сопоставлен с учетной записью в Системе и не допускалось анонимных, общих, групповых, резервных или дополнительных пользовательских учетных записей, доступных нескольким пользователям.

Принцип контроля доступа во всех режимах – во всех штатных и внештатных режимах функционирования Системы, а также на всех этапах разработки и эксплуатации, в Системе всем пользователям должны быть назначены определенные соответствующими правилами доступа полномочия.

Принцип «все, что не разрешено, запрещено» используется при проектировании Системы. В случае, когда в Системе создается новая учетная запись для нового пользователя, все привилегированные функции должны быть по умолчанию отключены.

Принцип наименьших полномочий состоит в том, что любой авторизованный пользователь (субъект или процесс, действующий от имени субъекта) в рамках стандартных процедур должен получать права доступа к защищаемой информации и защищенным ресурсам только при условии служебной необходимости. Любые полномочия пользователя, которые не используются им на постоянной основе, должны быть исключены из его роли, назначенной ему на постоянной основе. 

Принцип предоставления прав доступа к необходимой информации сужает доступ к информации, если дополняет более общий принцип наименьших полномочий. Согласно этому принципу, для каждого пользователя с назначенными полномочиями (ролью) администраторами должны применяться дополнительные ограничения по доступу к информации, которая не попадает в сферу его конкретных функциональных обязанностей.

Принцип разделения полномочий предотвращает ситуации, при которых одно и то же лицо ответственно за несколько критических операций в ИС, ошибки в которых могут привести к серьезным последствиям для организации, в том числе в связи с тем, что эти ошибки невозможно обнаружить и исправить в приемлемый промежуток времени. Разделение полномочий является также одной из ключевых мер безопасности для предотвращения злоумышленных и коррупционных действий персонала организации.
